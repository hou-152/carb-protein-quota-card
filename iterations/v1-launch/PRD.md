# 碳水蛋白质配额卡 · PRD · v1-launch

> 文件位置：`iterations/v1-launch/PRD.md`
> 配合项目根的 [BRIEF.md](../../BRIEF.md) 阅读。这份 PRD 描述首版要做的事。

## 1. 项目背景
这个项目基于既有的《碳水和蛋白质配额表｜逐格对照录入版》重新变式为一个独立网页工具。它不是个人主页的一部分，也不是医疗或专业备赛产品，而是一个面向新手的生活化配额查询器。

参见：[BRIEF.md](../../BRIEF.md)

## 2. 本次目标
v1 上线后，用户可以在一个页面内完成原工具饮食逻辑的核心路径：输入基础信息，得到基础配额；如果有有氧，能看到有氧消耗如何增加饮食热量；如果有训练时间点，能看到碳水和蛋白质如何分配到各餐。首版必须尊重原 Excel / 视频讲解里的数据关系，不能把它压扁成一个简单结果卡。

当前代码中的“碳水蛋白质配额卡”只是临时原型。正式 MVP 以 [ORIGINAL_LOGIC_AUDIT.md](./ORIGINAL_LOGIC_AUDIT.md) 为准重构。

## 3. 用户与关键场景

### 场景 1：减脂新手不知道今天吃多少
- **用户**：刚开始减脂、有或没有力量训练的人。
- **旅程**：选择性别、训练状态、目标、身高、体重，点击或自动生成结果。
- **结果**：看到每日碳水、每日蛋白质，若有力训则区分训练日和休息日。

### 场景 2：力量训练用户需要训练日 / 休息日区别
- **用户**：每周有规律力量训练，但不想自己算宏量营养素的人。
- **旅程**：选择“有力量训练”和“减脂 / 增肌”，得到两类碳水配额。
- **结果**：理解训练日可以吃更多碳水，蛋白质按每日配额执行。

### 场景 3：有氧用户需要知道多吃多少
- **用户**：做有氧的人，可能是为了制造热量消耗、改善心肺、爱好或被迫活动。
- **旅程**：输入有氧类型、时长或热量消耗，系统把每周消耗摊到每天。
- **结果**：看到有氧对应增加的饮食热量，以及这些热量优先加到碳水还是碳水 + 蛋白质。

### 场景 4：按训练时间分餐
- **用户**：力量训练时间不同的人，例如早饭前、午饭前、晚饭前或晚饭后训练。
- **旅程**：选择训练时间点。
- **结果**：看到训练日前后各餐的碳水和蛋白质分配，训练后餐作为全天最大碳水餐。

### 场景 5：结果不在表格范围内
- **用户**：身高体重组合落在原始截图表格空白区域的人。
- **旅程**：输入信息后匹配到 `-` 单元格。
- **结果**：看到明确提示“该组合不在当前表格范围内”，而不是错误数字。

### 场景 6：用户想截图保存
- **用户**：想把今天结果保存到相册或发给朋友的人。
- **旅程**：生成结果后看到一张视觉稳定的配额卡。
- **结果**：可以直接系统截图；v1 不必内置图片导出。

## 4. 页面结构

- `/` —— 单页工具：首页、输入表单、结果卡、解释和边界说明都在同一页完成。

## 5. 信息架构

### 首页 `/`
- **顶部说明区** —— 建立信任并说明这是什么工具。
  - 内容槽：工具名 / 一句话说明 / 非医疗建议提示
- **输入区** —— 收集计算所需条件。
  - 内容槽：性别 / 训练状态 / 目标 / 身高 / 体重 / 训练时间点 / 有氧消耗
- **BMI 与目标判断区** —— 还原原工具先判断体重阶段的逻辑。
  - 内容槽：BMI / 增肌或减脂提示 / 体重变化观察周期
- **基础配额区** —— 输出基础碳水和蛋白质。
  - 内容槽：匹配档位 / 训练日碳水 / 休息日碳水 / 蛋白质 / 空值提示
- **有氧补偿区** —— 说明有氧增加的消耗如何转成饮食热量。
  - 内容槽：每周有氧消耗 / 平均每日消耗 / 增加碳水 / 大量有氧提示
- **分餐区** —— 按训练时间点拆到各餐。
  - 内容槽：早餐 / 午餐 / 训练前 / 训练后 / 晚餐 / 可调整提示
- **解释区** —— 降低误读风险。
  - 内容槽：数字含义 / 查表原则 / 有氧与饮食互换关系 / 分餐优先级 / 空值处理
- **数据来源区** —— 说明数据来自已录入配额表，并保留版权与准确性边界。
  - 内容槽：来源描述 / 原始数据文件路径 / 必须署名 / 开源协议尊重说明

## 6. 输入与输出逻辑

### 输入
- 性别：男 / 女
- 训练状态：有力量训练 / 无力量训练
- 目标：减脂 / 增肌
- 身高：按性别对应档位选择
- 体重：允许选择档位；也允许输入数字后匹配最近体重档位
- 训练时间点：用于决定训练日分餐顺序
- 有氧：无 / 每周时长 / 每周消耗 / 每日消耗（具体取决于是否能拿到原有氧热量消耗表）

### 输出
- 有力量训练：
  - 训练日碳水 = 训练日碳水系数 × 体重
  - 休息日碳水 = 休息日碳水系数 × 体重
  - 每日蛋白质 = 蛋白质系数 × 体重
- 无力量训练：
  - 每日碳水 = 每日碳水系数 × 体重
  - 每日蛋白质 = 蛋白质系数 × 体重

### 特殊规则
- 如果单元格是 `-`，提示：该身高体重组合不在当前截图表格范围内。
- 无力量训练只有减脂表，没有增肌表；选择该组合时提示不可用。
- 所有结果四舍五入到整数克。
- 必须按结构化表格逐格查询，不允许用公式拟合替代。
- “复制结果文本”复制的是纯文本摘要，不是图片。文本必须包含输入条件、匹配档位、碳水 / 蛋白质克数和非医疗建议提醒。
- 如果没有原始有氧热量消耗表，不能自造运动项目消耗；只能允许用户手动输入有氧消耗，并清楚标注这是临时输入。
- 分餐比例必须来自原 Excel 或用户确认，不能按普通营养 App 的习惯重设。

## 7. 目标衡量

**主指标（上线后 30-90 天）：**
- 用户能在 30 秒内完成一次查询并理解结果。
- 核心结果卡在移动端首屏内可读，无文字溢出。

**漏斗指标（过程指标）：**
- 到达页面 → 看到工具说明和输入区。
- 填写信息 → 不需要打开说明文档也能完成。
- 生成结果 → 看到明确克数、档位和边界提示。
- 保存使用 → 结果卡适合系统截图。

## 8. 范围

**这一版会做：**
- 单页网页工具，但结构必须保留原工具的数据关系。
- 原始配额表结构化数据录入。
- 性别、训练状态、目标、身高、体重输入。
- 有力训 / 无力训两类输出。
- BMI 与目标阶段提示。
- 有氧消耗输入与饮食热量补偿说明。
- 训练时间点与分餐模块。
- 不可用组合与空白单元格提示。
- 结果卡与基本解释区。
- 复制结果文本按钮。
- GitHub Pages 部署。
- 完成部署后，把该项目加入个人主页项目区。
- 公开页面必须署名原作者 / 来源，尊重对方开源协议。

**这一版不做：**
- 用户账号、历史记录、云同步。
- 医疗、疾病、特殊人群建议。
- 食谱生成、餐次拆分、食物库。
- 自动识别体脂率或接入 Apple Health。
- 内置图片导出。
- 在没有原始 Excel 数据时，凭空补全有氧消耗表或分餐比例。

## 9. 风险与待解决问题

**已知风险：**
- 原始数据来自截图录入，必须保留人工核对空间。
- 当前缺少原始 Excel 的完整 23 张表，尤其是有氧热量消耗表和分餐比例表。
- 公开发布必须署名原作者 / 来源；如果无法确认具体开源协议文本，页面至少保留清楚的来源说明，并避免暗示数据归本项目原创。
- “建议”一词可能被误读为专业健康建议，文案要始终强调生活化参考。

**需要用户确认：**
- 原始项目 / 视频 / 开源协议的准确链接。
- 原始 Excel 文件或 23 张表的完整数据。
- GitHub 仓库名，默认建议 `carb-protein-quota-card`。
- 个人主页项目卡的展示文案和排序。
